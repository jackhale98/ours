# Review 0002: API (phase 2)

- Reviewer: independent agent that did not write the code (build plan §11)
- Date: 2026-11-03
- Scope: `apps/api/src/**`, migrations, `wrangler.jsonc`, tests; request schemas in `packages/core`
- First verdict: **No sign-off**, with seven conditions. Fixes below; re-review requested.

The reviewer confirmed most findings with probe tests (since deleted) and verified correct: hashed tokens and sessions, atomic single-use magic links and passkey challenges, origin/RP ID checks, atomic backup compare-and-swap, atomic invite claiming, push upsert guards (space, scope, owner, base rev), rev monotonicity in one batch transaction, pull filtering, CORS, generic errors, salted rate-limit keys, and that D1 enforces foreign keys (cascades run).

| ID | Severity | Finding | Status |
|---|---|---|---|
| H1 | High | Platform invocation logs would store client IPs and invite URLs | **Fixed:** `invocation_logs: false`; `pnpm check:worker` in CI guards it |
| H2 | High | Closed/invite-only sign-up bypass: one invite id created unlimited accounts | **Fixed:** the invite is claimed atomically for one new account; regression test |
| M1 | Medium | Device cap locked users out after 10 sign-ins | **Fixed:** logout removes an unused device; at the cap, devices without sessions then the least recently seen are evicted; tests |
| M2 | Medium | Per-address rate limit counted before Turnstile, so anyone could block an address | **Fixed:** bot check first; per-address limit now silently stops sending (no 429); test |
| M3 | Medium | Account enumeration by response timing | **Fixed:** lookup, token and email happen after the response (`waitUntil`); test that the response doesn't wait for email |
| M4 | Medium | Passkeys couldn't be listed/removed; adding needed no re-auth | **Fixed:** `GET /auth/passkeys`, `DELETE /auth/passkeys/:id`; adding requires a sign-in within 10 minutes; email notice on add; cap of 10; tests |
| M5 | Medium | Quota bypasses (leave-and-rejoin, races, tiny rows, concurrent pushes) | **Fixed:** space creation and invite accept check caps atomically in SQL; each record is charged ciphertext + nonce + 256 bytes; the storage check runs inside the push transaction (a guard insert aborts the batch); a failed join leaves the invite intact; tests |
| L1 | Low | Lost-race conflict could return another space's record | **Fixed:** re-select filtered by visibility; otherwise `rejected: not_allowed` |
| L2 | Low | Body read fully before size check | **Fixed:** streamed with a byte counter; test |
| L3 | Low | Large pulls could exhaust memory | **Fixed:** pages stop at 4 MB of ciphertext (at least one record) |
| L4 | Low | Rate limiter: per-isolate salt, IPv6 /128, shared binding, Turnstile fail-open | **Partly fixed:** IPv6 keyed by /64; with real email the API refuses to run without `RATE_LIMIT_SALT`. Turnstile stays optional for self-hosts (documented); separate bindings per purpose deferred |
| L5 | Low | Deletion left the user id in `updated_by` and `claimed_by` | **Fixed:** both cleared; test |
| L6 | Low | THREAT_MODEL described blob deletion on first fetch | **Fixed:** docs describe claim-on-fetch and erase-on-accept |
| L7 | Low | Unbounded passkey registration options / passkeys | **Fixed:** per-user rate limit and 10-passkey cap |
| Info | — | Duplicate credential id 500 | **Fixed:** 409 |
| Info | — | Pages `github.io` RP ID / origin shared with other project pages | **Documented** in SELF_HOSTING; use a custom domain for the public instance |
| Info | — | No absolute session lifetime; `DELETE /me` without re-auth; several live magic links | Accepted for now; revisit in phase 7 |
